# ローカル検証

`bash scripts/check.sh` を各コミット前に実行する。C++コンパイラ、PythonとPlatformIO、初期化済みADS1X15サブモジュールが必要。オンラインCIは使用しない。

- `bash scripts/test.sh`: 実際の管理クラスをホスト上で実行する。SD・時計等の境界だけをfakeへ置き換え、失敗を注入する。AddressSanitizer / UndefinedBehaviorSanitizerを有効化する。
- `bash scripts/check.sh`: 上記テストと差分検査後、ESP32用の`validation`と`offline`環境をビルドする。`PIO`環境変数でPlatformIO実行ファイルを指定可能。
- `validation`は公開のダミー設定をプリプロセッサで選択する。`secure/`の実設定・証明書を読み込まず、変更もしない。検証バイナリは実機へ書き込まない。
- `m5stack`は既存の実機用設定。夜間作業では使用しない。

テストはファイル名衝突、保存失敗、圧力値の保持から開始し、各修正と同時に障害・境界・並行処理の回帰ケースを追加する。実機でのSD媒体永続化、ADC配線、AWSへの実接続、スケジューラの遅延分布はホスト試験では証明できないため、別途実機試験手順と未検証事項を記録する。

## R2-B01: Wi-Fi非同期復旧

接続／再接続は非同期要求だけを発行し、ポーリングのたびに実状態をatomicな表示用状態へ反映する。初回10秒・再接続5秒の待機を廃止した。テストでは接続要求の翌ポーリングで成功するケース、切断・再試行、32bit時計の周回を確認する。

## R2-B02: NTPの非同期復旧

時刻取得の確認は全経路で`getLocalTime(..., 0)`を使う。起動時に待たず、Wi-Fi接続時と未同期時の30秒間隔でSNTPへ同期を要求する。遅れて時刻が確定した場合は次の確認から有効になる。通信タスクで短くポーリングし、時刻確定前のTLS接続は抑止する。ホスト試験では時計取得に待機時間を指定すると仮想時計が進むfakeを使い、オフライン起動・NTP不達・遅延成功・Wi-Fi復旧の全経路に待機がないことを確認する。

## R2-B04: 画面復帰時の一定入力

画面初期化で圧力文字のキャッシュを無効化する。同じ圧力のまま画面を繰り返し消しても、最初のサンプルで再描画し、その後の同値は重複描画しないことを実際のDisplayManagerと描画fakeで検証する。

## R2-B05: 波形のピークと時間軸

20秒を2px幅×138列へ対応付け、各列に両チャンネルの最小／最大を残す。列位置は64bit取得時刻で決め、欠測を詰めない。時計だけ進んでも古い列を消し、約1秒（7列、約1.015秒）の移動空白帯を維持する。遅れて届いた可視範囲内の値は元の列へ描き、窓より古い値は新しい周回を上書きしない。外枠を維持し、線幅と上下左右の余白は2px。テストは1列内のパルス、1秒の取得空白、長時間の停止、古い滞留値、描画の端点を確認する。

## R2-B06: 削除確認

一覧のBは確認画面を開くだけとし、完全なファイル名・連番・バイト数を表示する。確認画面のBで削除、Cで取消。選択名は確認開始時に固定し、実行中の再押下や一覧の変化で対象を変えない。成功／失敗はCで閉じるまで表示する。テストは未確認の実行拒否、取消、対象の固定、失敗表示と完全名の表示を確認する。

## R2-B07: 起動リソース失敗

キュー・計測タスク・通信タスクとMQTT内部リソースの確保結果を検査する。計測系が起動していない場合はStateManager自身がREC遷移を拒否し、波形画面に失敗したリソースを表示する。通信系だけの失敗ではSD記録を使用できる。テストは各生成失敗に対応する起動手順の分岐を注入し、REC抑止とファイル画面の利用可否を確認する。MQTT内部バッファ確保失敗時に全公開操作が安全に戻ることも確認する（R2-B08で動的mutexを除去し、この障害注入へ更新）。

## R2-B08: MQTT最新値配信と結果管理

PubSubClientの操作を通信タスクへ集約し、UI／取得側は短いクリティカルセクションで最新値スロットを置き換えるだけにする。送信可否判定・publish・試行／成功時刻の更新を同じ所有者で実行する。同期I/Oを保持したまま共有ロックを取らない。接続状態とカウンタは同じロックでコピーするスナップショットとして公開する。

約500msごとのQoS 0最新値配信であり、全履歴・古い失敗値の再送はしない。接続復帰時も最新スロットを取り直し、取得から1秒超の値は破棄する。試行間隔は送信完了後の実時計で判定し、失敗では成功時刻を進めない。記録停止は待機スロットを消すが、すでに通信タスクが取り出して送信中の1件までは取り消せない。`session`・`sequence`は起動中での識別用であり再起動を越えた一意IDではない。

実MQTTManagerと通信境界fakeを使い、publish失敗、3秒の送信停止中の200件の新規投入、接続途中の更新、停止、古い値の拒否、時計周回、通信バッファ不足を検証する。実AWSへの接続は行っていない。
## R2-A01: SD失敗と復旧

ヘッダ／本文はCRLFを含む全長を書けた場合だけ成功とする。途中で失敗したCSVは調査用に残し、同じファイルへの追記は停止する。画面のSD ERRは記録を停止→再開始し、再マウント・新規ファイル作成が成功するまで保持する。SD障害だけではMQTTの記録セッションを停止しない。

ホスト試験は全ての短い書き込み長（0バイト、本文途中、CR/LF欠落）、open失敗、APIが報告するflushエラー、別ファイルへの復旧を注入する。ESP32の`File::flush()`と`close()`は戻り値がなく、媒体内部の永続化失敗を全て検出できるAPIではない。書き込み長と`getWriteError()`で判定できる範囲を越えた電源断耐性は保証しない。実機では容量不足・抜去・再挿入後の新規記録を確認する。

## R2-A02: 取得時刻

サンプル時刻は`esp_timer_get_time()`から求める起動後64bitミリ秒。CSVは記録開始時の同じ時計との差分、MQTTの`timestamp`は取得時の起動後ミリ秒でありUNIX時刻ではない。NTP補正や32bit `millis()`の周回から独立する。保存／送信の遅延によって取得時刻を取り直さない。テストは32bit境界をまたぐ取得、遅延消費、開始前サンプルの拒否、MQTTペイロードを確認する。

## R2-A03: 記録境界

開始・取得サンプル・停止を同じFIFOへ投入する。投入操作だけを短いクリティカルセクションで直列化し、取得値がFIFOへ渡された瞬間をセッションへの所属境界とする。CSV開始基準は開始イベントの時刻。ボタン操作後に消費しても、待機時の値は記録せず、停止イベントより前に受理した記録値は最後まで処理する。停止時の全キュー破棄は行わない。

サンプルには容量2件の予約枠を使わせず、停止イベントの枠を確保する。連打で新しい開始を受理できない場合はRECへ遷移しない。停止後のファイル確定はキュー排出完了時になる。テストは停止・再開始まで消費を遅らせた2セッション、待機値の除外、満杯時の停止受理、SD失敗時のMQTT継続を確認する。

## R2-A04: 保存・通信の分離と負荷試験

取得タスクから保存FIFO（512件、境界予約2件）、表示FIFO（512件）、通信の最新値メールボックス（1件）へ独立して渡す。保存・一覧・削除は保存タスク、TLS／MQTTは通信タスクだけが実行する。UIの4件制限は表示処理だけに適用する。SDとLCDは同じSPIバスのため、画面描画は保存処理中に待たずにスキップする。ボタン読み取りと開始／停止要求はSPI待ちの外側で実行する。

SDファイルはセッション中保持し、最大1,024バイトでまとめ書きする。1秒ごとと停止時にflushし、停止時にcloseする。電源断ではアプリ側の最大1秒分の未flushデータに加え、媒体側キャッシュのデータも失われ得る。SD失敗は次のwrite/flushで検出される。セッションの末尾コメントへ保存キューの欠落数・最大使用数を残し、シリアルにもセッションIDと累積欠落数を5秒ごとに出す。欠落をゼロと保証できない負荷では、その事実を時刻の飛びとカウンタで識別する。

ホスト試験の合格基準:

- SD書き込みが終了していない間にも停止要求が受理され、画面描画用ロックの取得は即失敗して戻る。
- 保存キューが満杯でもネットワークのメールボックスは最新サンプルを保持する。
- 保持容量を越えた14件の欠落が、そのセッションのCSV末尾に14件として記録される。
- 100件保存してもファイルopenは1回、closeは停止時の1回のみ。期限・停止時に末尾まで書かれる。
- ファイル一覧／削除はUIから要求した時点ではSDへアクセスせず、停止イベントの排出後に実行する。

実機試験（未実施）: 通常カード・遅いカード・AWS不達で各10分記録し、100Hzの取得間隔分布、欠落数、キュー最大値を比較する。通常負荷の目標は欠落0、Aボタン離上から停止要求受理まで100ms以内。SDを5秒以上停止させる場合は欠落数の一致とボタン応答を確認する。表示は共有SPIが空くまで遅延してよいが、停止要求自体は遅延させない。シリアルの要求受理時刻とCSVの最終取得時刻、末尾コメントを照合する。実媒体の遅延値をホスト試験の結果として扱わない。

## R2-A05: 運転中のADC障害

I2C書き込み・読出し長・設定値を検査する専用ADS1015読取経路へ変更した。設定は従来と同じAIN0／AIN1、±6.144V、3300SPS。レジスタの解釈は[TI ADS1015データシート SBAS473F](https://www.ti.com/lit/ds/symlink/ads1015.pdf)の7.5.4節と8節に基づく。

1ペアの変換に8msの期限を設け、Wireの転送タイムアウトは2msにする。期限を過ぎた新しい転送は開始しないため、ソフトウェアの待機目標上限は8ms＋最後の転送2ms（RTOSによるプリエンプトを除く）。正常取得後に限り2チャンネルをまとめてキューへ渡す。失敗時はADC異常にし、その記録セッションへ停止イベントを送る。1秒ごとに再取得し、正常なペアが取れたら待機状態へ復帰する。記録の再開はAボタンで明示的に行う。期限超過後に追いつこうとして連続取得しない。

ホスト試験は全転送位置のNACK、短い読出し、設定不一致、変換未完了、時計の周回を注入する。途中まで取れたチャンネルを正常なペアとして渡さないこと、異常中のサンプル抑止と停止イベント、1秒後の復帰時も自動RECしないことを確認する。実機ではREC中にADCを切断・再接続し、ADC異常表示、CSVの終了、ボタン応答、再開始を確認する（未実施）。

### R2-A01追補: 再マウントのCSピン

M5StackライブラリのSD初期化はGPIO4を指定するが、選択中のArduinoボードvariantの既定`SS`はGPIO5である。`SD.end()`後に引数なしで再マウントするとGPIO5へ変わるため、SDManagerでも`SD.begin(4, SPI, 40000000)`を明示する。初回と障害後の両方でGPIO4が選択される回帰試験を追加した。
## R2-C01: 一覧キャッシュと未同期名

ディレクトリ走査時に名前とサイズを一度に取得してキャッシュする。記録開始／終了／書き込み失敗／再マウントで無効化し、削除成功は該当項目を消す。選択移動ではSDの走査やサイズ取得のためのopenを行わない。日時名、起動グループ名、従来の未同期名の順に分け、同じグループ内は数字を数値として比較する。

新しい未同期名は`pressure_log_boot_<起動グループ番号>_<64bit起動後ms>.csv`。そのSDに残っている起動グループの最大値＋1を最初の未同期記録時に決め、同じ起動中は再マウントでも維持する。旧ログの起動日は復元できず、NTP名と未同期名の間の絶対的な新旧は主張しない。全ログを消した場合、次の起動で番号は再利用され得る。外部機器でカード内容を変更した場合は再マウントまたは再起動する。

503件の混在ログで数値順を確認し、10回の一覧・全サイズ参照で追加openが0回であること、起動／再マウント識別、削除失敗時のキャッシュ保持を検証する。

## R2-C02: オフライン構成

`pio run -e offline`は`PRESSURE_OFFLINE`を指定する。ネットワーク設定／証明書をincludeせず、Wi-Fi／TLS／MQTTのインスタンスと通信タスクを生成しない。NetworkServiceは待機も外部通信もしない実装へ切り替わる。SDは時刻源なしで記録し、画面にOFFLINEを表示する。通常の`m5stack`構成は従来どおりローカル設定を利用する。

ローカルゲートはホスト試験もonline／offlineの両構成で実行する。offlineではWi-Fi開始・NTP要求・MQTT接続が全て0回で、SD記録開始から停止まで行えることを検証する。ESP32ビルドも公開ダミー設定のvalidationと、ダミー設定すら使わないofflineを対象にする。実機への書込みは行わない。

## R2-C03: 所有関係と統合試験

LoggerApplicationが管理クラスとキューの寿命を所有し、FreeRTOSタスクには所有者ポインタを渡す。画面・ボタン・一覧選択・StateManagerはUIだけが操作する。センサーはAcquisitionService、SDと一覧キャッシュはStorageService、Wi-Fi／NTP／TLSはNetworkServiceの担当タスクだけが操作する。不要になった2,000件×2のグローバル配列、表示用の未使用引数、stateChangeTime、ファイル名の未使用整形関数、重複した起動処理を削除した。

共有サンプル／境界はキュー、MQTTの入力と状態は短いクリティカルセクション、可用性と欠測数はatomic、SD一覧結果はmutex＋swapで受け渡す。SD／LCDの共有SPIは保存側のmutexと描画側のtry-lockで直列化し、ボタン処理では待たない。時刻整形は待機なしのRTC読み取りで、不要な時刻同期フラグは持たない。

同じLoggerApplicationのsetup/tickと各ワーカーのstepをホストで実行する統合試験を追加した。実際のボタン列による開始・停止、削除確認・取消・実行、SD書込み中の停止受理、タスク生成失敗時のREC抑止と画面操作を確認する。待機中の削除確認画面を毎周回消去する処理も除き、画面や一覧が不要に更新されないことを検証する。
