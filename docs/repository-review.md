## A：最優先

### A-01 ログファイル名の重複による上書き

- 根拠: [SDManager.cpp](../src/SDManager.cpp) 38〜70 行。日時は秒単位、未同期時は起動後の `millis()` のみで命名し、存在確認なしに `FILE_WRITE` で開く。
- 発生条件・影響: 同じ秒内の記録再開、または再起動後に同じ経過ミリ秒で記録を開始すると名前が重複する。ローカル SDK の `libraries/FS/src/FS.h` では `FILE_WRITE` は `"w"` であり、既存ログを切り詰める。
- 修正案: 既存ファイルを上書きしない作成手順と連番の付与を実装する。日時だけに一意性を依存しない。
- 完了条件: 同一時刻を固定した連続開始、未同期での再起動を模擬し、既存 CSV の内容が保持されること。

### A-02 SD 障害と記録状態の不整合

- 根拠: [SDManager.cpp](../src/SDManager.cpp) 77〜104 行、[StateManager.cpp](../src/StateManager.cpp) 32〜37・80〜84 行。`logData()` は open 失敗を通知せず、`println()` の書き込み結果を無視する。状態はファイル作成の成功確認前に `RECORDING` になる。
- 発生条件・影響: 記録中のカード抜去・容量不足などで保存できなくなっても `recording` と `sd_available` が更新されず、`SD:REC` が続く。開始失敗時にもシステム状態と SD 状態が食い違う。
- 修正案: 作成・書き込み結果を呼び出し元へ返し、書き込みバイト数、エラー状態、失敗件数を管理する。SD 記録と MQTT のみの動作を区別し、画面に保存失敗を表示する。
- 完了条件: open 失敗・短い書き込み・容量不足を模擬して、保存できない状態が明示されること。カード復旧後の再開方針も定義する。

### A-03 通信処理によるサンプリング停止

- 根拠: [main.cpp](../src/main.cpp) 173〜219 行、[WiFiManager.cpp](../src/WiFiManager.cpp) 52〜70 行、[MQTTManager.cpp](../src/MQTTManager.cpp) 23〜45 行。計測の前に同じループで再接続し、Wi-Fi 再接続は最大約 5 秒の待機を含む。MQTT 接続も同期呼び出し。
- 発生条件・影響: 通信断で 10 ms 周期の読み取りが数秒停止する。遅延後も取得は 1 サンプルのみで欠測は記録されない。`now` は通信待機より前に取得され、時間判定にも古い値を使う。100 Hz は設定値であり保証されない。
- 修正案: 計測を通信・描画・保存から分離し、取得時刻つきの有界キューで受け渡す。再接続待機を非同期化し、Wi-Fi 未接続時の MQTT 接続を抑止する。キューあふれと欠測数を可視化する。
- 完了条件: Wi-Fi 切断・MQTT 応答なし・NTP 不達の各条件で、取得間隔の分布、最大遅延、欠測数を実機測定し、許容基準を満たすこと。過去のサンプルを後から取得した扱いにしない。

### A-04 圧力値の制限により異常値を識別できない

- 根拠: [main.cpp](../src/main.cpp) 205〜219 行。1〜5 V を 0〜1 MPa に変換した後、SD・MQTT に渡す前に 0〜0.5 MPa に制限する。
- 発生条件・影響: 0.8 MPa 相当も 0.5 MPa として保存され、下限未満も 0 MPa になる。画面の表示範囲なのか、測定仕様なのかが混在している。0.5 MPa 上限が意図的かは要件確認が必要。
- 修正案: ADC 生値・変換値・範囲外フラグを保持し、表示用の制限だけを描画側に置く。センサーの実仕様に基づく分圧比・変換係数・校正値を設定化する。
- 完了条件: 1 V、3 V、5 V 相当の入力で、変換値 0、0.5、1 MPa と表示範囲外の扱いを確認する。仕様上保存範囲を制限する場合も元値と異常状態を追跡できること。

### A-05 ADC の初期化失敗を無視する

- 根拠: [main.cpp](../src/main.cpp) 150〜153 行。`ads.begin()` の成功を確認せず設定と読み取りへ進む。画面にも ADC の正常・異常状態がない。
- 発生条件・影響: ADS1015 未接続・I2C 配線不良を正常な計測開始と区別できない。失敗後の具体的な読み取り挙動はライブラリ・実機での確認が必要。
- 修正案: 初期化結果を検査し、失敗時は計測を無効化してエラー表示する。運転中の通信失敗も検出し、無効サンプルを正常値として記録しない。
- 完了条件: ADC 未接続で起動し、明示的なエラーになり、正常データとして保存・送信されないこと。

## B：次に対応

### B-01 Wi-Fi 復旧後の内部フラグが更新されない

- 根拠: [WiFiManager.cpp](../src/WiFiManager.cpp) 33〜49・74〜75 行。内部フラグが false の間に Wi-Fi が非同期で接続済みになると、`checkConnection()` のどちらの分岐にも入らず false が残る。
- 影響: 実際は接続していても表示は未接続となり、`wifiManager.isConnected()` に依存する NTP 再試行も抑止される。
- 修正案: 実際の接続状態または接続イベントからフラグを一元更新する。
- 完了条件: 再接続待機終了直後に接続が成立するケースで、画面と NTP 判定が復旧すること。

### B-02 時刻同期の復旧とタイムアウト

- 根拠: [main.cpp](../src/main.cpp) 191〜198 行、[TimeManager.cpp](../src/TimeManager.cpp) 6〜12・39〜65 行。起動時の Wi-Fi 失敗後、NTP の再初期化は 30 分間隔の判定まで待つ。待機は経過時間ではなく試行回数で制限される。
- 影響: 接続復旧後もしばらく日時付きログを使えない。ローカル SDK の `Arduino.h` では `getLocalTime()` の既定待機は 5 秒なので、10 回の試行と各 1 秒の delay は時刻未取得時に約 60 秒になり得る。ループ内で実行すると A-03 を悪化させる。
- 修正案: Wi-Fi 復旧時に同期を開始し、明示的な短い確認タイムアウトと実時間の期限を使う。後から時刻が取得できた場合も内部フラグを更新する。「30 分ごとに再同期」というコメントと、未同期時だけ呼ぶ実装の意味を統一する。
- 完了条件: オフライン起動後の接続・NTP 不達・遅延成功で、計測を止めずに同期状態が正しく変わること。

### B-03 削除前の確認と対象ファイルの識別

- 根拠: [main.cpp](../src/main.cpp) 76〜102 行、[DisplayManager.cpp](../src/DisplayManager.cpp) 161〜164 行。一覧で B を押すと即削除する。長い名前は先頭 22 文字だけになり、日時形式の名前では時分秒が見えない。
- 影響: 同日に取得した複数ログの区別が難しく、誤削除しやすい。
- 修正案: 削除確認画面または長押し操作を設け、対象の完全な日時・サイズを確認できるようにする。削除失敗も画面へ通知する。
- 完了条件: 同日の複数ファイルを識別でき、キャンセル時には保存内容が変わらないこと。

### B-04 画面再初期化後の数値が再描画されない

- 根拠: [DisplayManager.cpp](../src/DisplayManager.cpp) 6〜12・67〜77 行、[StateManager.cpp](../src/StateManager.cpp) 67〜75 行。画面クリア時に前回表示値を無効化しない。
- 影響: 圧力が一定なら、一覧から戻る・記録を停止する操作で圧力数値が消えたままになる。
- 修正案: 画面初期化で表示キャッシュを無効化し、次回は必ず数値を描く。
- 完了条件: 一定入力で画面遷移と記録停止を繰り返しても数値が表示されること。

### B-05 波形のピーク消失と座標の境界不整合

- 根拠: [DisplayManager.cpp](../src/DisplayManager.cpp) 48〜64 行。2,000 サンプルを 278 列へ写像し、同じ列を毎サンプル消去する。0 MPa の y 座標は 99 / 199 で、消去範囲 21〜98 / 121〜198 の外になる。
- 影響: 1 列に含まれる約 7〜8 サンプルの途中のピークが消える。0 MPa の点は枠線に重なり、通常の列消去で消えない。
- 修正案: 列ごとの最小・最大値を集約して描画する。座標を枠内に統一し、時間軸も実際の取得時刻と整合させる。
- 完了条件: 同一列内の短いパルスを表示でき、0 / 0.5 MPa が枠を上書きしないこと。

### B-06 セットアップ資料と MQTT 設定の不一致

- 根拠: [AWS_SETUP.md](../AWS_SETUP.md) 29・56・90・111 行、[config.h.example](../secure/config.h.example) 9 行、[MQTTManager.cpp](../src/MQTTManager.cpp) 64〜65 行。
- 影響: 手順は存在しない `.template.h` のコピー、`main.cpp` 内の認証情報編集を案内する。ポリシー例・購読先・未使用の `aws_iot_topic` は `pressure_logger/data` だが、実装は `ch0` / `ch1` に送信する。README のリンク先としても不整合が残る。
- 修正案: 実在する `.example` と `secure/config.h` に統一し、トピック設定と送信先・ポリシー例・購読例を一致させる。README の「録画」を「記録」に修正し、100 Hz が目標周期であること、I2C 配線・ADC アドレス・電源条件も明記する。
- 完了条件: 新規チェックアウトから手順を追い、設定ファイル作成と両チャンネルの受信を確認できること。

### B-07 テスト・CI と依存環境の再現性

- 根拠: [platformio.ini](../platformio.ini) 11〜18 行、[test/README](../test/README)。対象コミットの `test/` は説明ファイルのみで、`.github/` のワークフローはない。プラットフォームはバージョン未指定、ライブラリは範囲指定。ADS ライブラリはサブモジュールのコミットで固定されている。
- 影響: 計測変換・状態遷移・保存障害の回帰を機械的に検出できず、環境の更新でビルド結果が変わる可能性がある。PR 必須だけでは検証の通過を保証しない。
- 修正案: 変換、ファイル名衝突、保存失敗、非同期復旧、画面キャッシュの振る舞いをテストする。既知の動作バージョンを固定し、秘密情報を含まないテスト設定で CI ビルドする。CI が安定したら PR の必須チェックに設定する。
- 完了条件: クリーン環境からサブモジュール込みでビルドでき、主要な障害ケースの回帰を CI が検出すること。

## C：計画的に対応

### C-01 SD 書き込みをまとめて行う

- 根拠: [SDManager.cpp](../src/SDManager.cpp) 95〜103 行。目標 100 Hz の各サンプルで open、文字列生成、書き込み、close を実行する。
- 暫定対応: REC 中もボタン入力を処理できるよう、[main.cpp](../src/main.cpp) では1回の `loop()` で処理するキューを `max_samples_per_loop = 4` に制限している。100 Hz を欠測なく処理するには `loop()` が平均40 ms以内で一周する必要があり、SD書き込みなどを含む消費速度が100 samples/sを下回るとキューが滞留する。512サンプルのキューが満杯になると `dropped_sample_count` が増え、以後のサンプルが欠落するため、この制限は操作性を保つための暫定措置とする。
- 改善案: ファイルを記録期間中保持し、取得時刻付きのデータをまとめて書く。定期 flush・停止時 close・電源断時の許容損失を明確にする。A-02 の失敗検知と A-03 の計測分離を先に整備する。
- 確認方法: 実機で書き込み遅延の分布と最大値、バッファ使用量、電源断後のログ復旧可能範囲を測定する。現時点で SD 遅延の実測値はない。

### C-02 MQTT の時刻・欠測・重複を追跡できる形式にする

- 根拠: [MQTTManager.cpp](../src/MQTTManager.cpp) 53〜79 行、[StateManager.cpp](../src/StateManager.cpp) 123〜132 行。起動後時刻だけを付け、同じ内容を 2 トピックへ送り、失敗しても送信時刻を更新する。未送信データの再送処理はない。
- 改善案: 最新値配信でよいか、全データの到達が必要かを決める。必要に応じてセッション ID・連番・取得時刻・同期状態を追加し、保存キューと受信側の重複排除を設計する。2 トピックの目的も明確にする。
- 確認方法: 片方の送信失敗、切断・再接続、再起動を模擬し、欠測と重複を識別できること。完全配信が必須なら優先度を B 以上へ引き上げる。

### C-03 ファイル一覧の応答速度と並び順

- 根拠: [main.cpp](../src/main.cpp) 52〜62・89〜102・112〜121 行、[SDManager.cpp](../src/SDManager.cpp) 106〜136 行。選択移動ごとに全件一覧取得と全件サイズ取得を行い、名前の辞書順で降順ソートする。
- 影響・改善案: ファイル数増加に伴う遅延を避けるため一覧をキャッシュし、入場・削除時に更新する。未同期名は `pressure_log_900.csv` が `pressure_log_1000.csv` より前になり、再起動をまたぐ時系列も表現できないため、セッション情報と数値による整列方針を決める。
- 確認方法: 数百件のログと日時・未同期名の混在で、選択の応答時間と並び順を確認する。

### C-04 オフライン計測を独立して利用可能にする

- 根拠: [main.cpp](../src/main.cpp) 3〜4・33〜35・141〜164 行。AWS ヘッダを無条件に要求し、接続機能を常時初期化・維持する。一方 [README.md](../README.md) 20 行は AWS 利用を任意のように説明する。
- 改善案: ネットワーク無効のビルド設定または運用設定を設け、SD のみで開始できるようにする。A-03 の改善と合わせてオフライン時の計測周期を維持する。
- 確認方法: AWS 証明書なしの設定でビルド・起動でき、SD 記録が継続すること。

### C-05 状態・描画データの所有関係と未使用処理を整理する

- 根拠: [StateManager.h](../src/StateManager.h) 12〜15・26 行、[DisplayManager.cpp](../src/DisplayManager.cpp) 48 行、[SDManager.cpp](../src/SDManager.cpp) 175〜195 行、[MQTTManager.cpp](../src/MQTTManager.cpp) 9 行。
- 改善案: グローバルな波形バッファを専用クラスへ移し、描画で使っていない配列引数と未使用の `stateChangeTime` を整理する。`PubSubClient` の所有を明確にするため値メンバー化等を検討する。現状の一度だけの `new` を継続的なメモリリークと断定はしない。
- 補足: 未使用の `getFileTimestamp()` は日時を `YYYY:MM:DD:hh:mm ss` に変換するため、利用するなら修正し、不要なら削除する。ファイル一覧更新処理の重複も共通化する。
- 確認方法: 外部動作を維持しながら、圧力変換と状態遷移をハードウェアなしで検証できる構造にする。
